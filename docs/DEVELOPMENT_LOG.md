# 开发记录与工程决策

以下按实际迭代阶段记录，日期均为 2026-10-15。记录关注可验证的工程结果，不将某次模型成功输出扩大为系统可靠性结论。

## 阶段一：明确范围与完成确定性原型

从多人点餐中的私人条件和公平问题出发，确定“只生成与确认餐单，不创建订单”的原型范围。先实现本地偏好评估、固定候选排序、隐私字段约束及前端交互，使评分规则可以在没有模型、没有 Token 的情况下测试。

决策：不用一个大模型同时掌握所有个人原文并负责打分。个人硬条件由确定性代码执行，协调模型只使用可见的公共信息和反馈。

## 阶段二：连接真实麦当劳 MCP

接入官方 Streamable HTTP MCP 服务，验证时间、营养、门店、菜单、详情与核价六类工具。实现工具允许列表、官方返回结构解析、商品数量检查、营养缺失处理和最终价格复核。

决策：不把模型记忆中的商品和价格当作业务事实；也不把缺失营养数据当作 0，避免错误通过营养约束。当前仅选择可核实单品子集，不处理复杂套餐子项。

证据：`evidence/live-readonly.json`。

## 阶段三：从固定演示到真实模型协商

增加本地 Node.js API 和增量轨迹。真实模型通过 `submit_table_proposals` 返回结构化候选；浏览器提供匿名评分，第二轮起附上少量本地可接受组合。最多三轮，无共识则明确失败。

早期千问版跑通两轮模型协商和最终核价，并完成真实浏览器确认、下载验收。之后仍保留固定数据模式，避免在网络或额度异常时冒充真实结果。

决策：实际架构是一位大模型协调者加多位规则评估器，而不是多个独立大模型实例。文档明确这一边界。

建立个人公开仓库 `amazingLH/mcd-secret-table`，配置 GitHub Actions 自动测试、构建及 GitHub Pages。公开站点仅运行固定数据，密钥和真实调用保留在本机。

决策：复用一个持续维护的个人仓库和一个报名 Issue，保留提交历史，不重复申请，也不修改官方评论。

## 阶段五：模型费用保护与兼容性适配

发现“配置了 Key 就可调用”的默认行为缺少额度核实环节，增加计费确认门：默认离线演示，真实调用需要当前模型名称与确认名称一致。收到免费额度保护错误后停止，不关闭云端开关、不切换付费模型。

根据账户持有人提供的额度截图，从有可用额度、支持工具调用的对话模型中选择 `deepseek-v4.1-flash`。该选择依赖当时截图中的账户状态，不能推导为所有用户永久免费。embedding/rerank 不用于餐单生成。

兼容性测试发现：同一模型响应可能包含合法候选和超预算候选。原实现整批拒绝，浪费有效方案并触发修正请求。改为逐份使用相同严格规则检查：合法候选进入评估，非法候选淘汰，全部非法才重试。未放宽预算规则，也没有用程序伪造模型候选。

在每次可解析模型返回时记录 responseId 和 Token，校验重试累计进轮次用量，避免只统计最后一次成功调用。成功验收两轮共 4051 Token，但这不包含历史连接、失败测试等其他调用，也不能替代账单。

结果：DeepSeek 两轮获得全员接受，官方报价 ¥74.50，最低满意度 85；本地测试扩展至 31 项。

## 阶段六：提高可解释性与项目可复现性

根据实际使用反馈，补齐三类可读性缺口：

1. 商品编码与匿名编号缺少说明：按本轮菜单补“编号（名称）”，`utility` 改为满意度，仅改变显示，不增加模型调用。
2. 多个合格候选与最终结果容易混淆：增加唯一采用标记、候选详情、接受人数、最低/平均分，以及最终结果中的方案编号。
3. 无法从首页了解实现过程：增加产品说明、技术架构、运行手册、开发记录与测试说明，并把它们链接到 README。

增加编号边界、重复标注、当前菜单映射、唯一采用标记与核价状态测试，本地回归扩展至 37 项。网页文案和状态展示可在离线模式验收，不为文案修改额外消耗百炼额度。

## 阶段七：轮次术语与用户提示精简

给 `r1` 与 `r2-p1` 增加轮次和方案括号释义，保留协议原始编号。将页尾工程化长说明改为三条简短使用提示，保留隐私、真实核价和费用边界，详细实现仍放在技术文档。增加边界及幂等回归，当前本地测试为 39 项。

## 持续成立的限制

- 同一浏览器模拟多人，不是多设备隔离。
- 匿名评分和可接受组合可能泄露偏好，不提供密码学隐私保证。
- 启发式满意度尚未通过真实用户研究标定。
- 仅搜索已核实单品子集，不保证最优套餐、最便宜组合或每次都能达成共识。
- 无下单、支付和优惠券交易能力。
- 自动化测试、一次真实验收和浏览器截图分别证明不同方面，不能互相替代。

后续可研究多设备会话、经过授权的持久化、更多餐品覆盖、真实用户评估与更细粒度的信息泄漏分析。以上均为未来方向，不属于当前已交付能力。
