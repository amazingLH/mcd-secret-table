# 测试、证据与复现

## 1. 三层验证

| 层次 | 入口 | 能证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 本地自动化 | npm test；npm run build | 确定性规则、输入边界、显示转换、类型与构建 | 不能证明外部服务当前可用 |
| 真实服务验收 | npm run mcp:verify；npm run agent:verify | 特定时间、门店、合成条件下的真实调用链 | 不能保证其他输入成功或跨时间不变 |
| 浏览器验收 | evidence/BROWSER_QA.md；界面截图 | 实际页面交互与结果可见性 | 不代替业务接口与算法测试 |

## 2. 当前自动化覆盖

截至本轮更新，共 39 项测试，6 个测试文件。`npm test` 不调用真实百炼模型或官方 MCP，不消耗模型额度。

| 文件 | 关注点 |
| --- | --- |
| tests/negotiator.test.ts | 确定性、公平排序、公共输出不包含原始私人字段，以及独立动作门 |
| tests/mcp.test.ts | MCP 只读策略、工具与响应处理等边界 |
| tests/api.test.ts | 本机 API 的跨源限制与私人字段拒绝 |
| tests/liveAgent.test.ts | 官方营养、未知商品、人数/预算、部分候选过滤、最终报价对应与分摊 |
| tests/model.test.ts | 默认禁止调用、模型变更需确认、拒绝 embedding、免费保护错误停止、非千问兼容 |
| tests/presentation.test.ts | 商品/参与者/轮次/方案编号释义、避免重复/误匹配、当前菜单映射、唯一选中、核价与演示状态区分 |

独立的 `actionGate` 具有确认状态的单元测试，但当前实时应用没有创建订单执行路径；这不代表项目支持确认后真实下单。

## 4. 可读性改动怎样复现

1. 本机或公开站点进入离线演示，运行默认条件。
2. 候选区出现唯一“演示选中”，最终区显示同一方案编号。
3. 展开该候选，查看各人的餐品名称、编码、接受状态和分数。
4. 展开评分规则，确认硬条件、55 分门槛以及最低/平均分排序有解释。
5. 修改任一条件，已有结果应清空，不允许沿用旧方案。
6. 编号 `1440/1450` 的真实说明样例由 `tests/presentation.test.ts` 覆盖；不需要为验证括号显示再请求模型。

离线 fixture 的商品 ID 与实时官方商品 ID 不同，且不能把离线选择称为“官方核价后通过”。

本轮已在真实浏览器完成离线 UI 验收：选中候选数量为 1，编号 `p2` 与最终餐单一致，候选详情与评分规则可展开，1264 像素宽视图未发现横向溢出。记录与截图见 [BROWSER_QA.md](../evidence/BROWSER_QA.md)。

## 5. 发布检查

```powershell
npm test
npm run build
node --import tsx scripts/check-release.ts
git diff --check
```

发布检查比较官方参赛声明，核对必需文件，检查追踪文件中是否出现本机实际凭据字节。它不是通用安全审计，也不能证明不存在任何未知形式的敏感信息。真实配置文件、依赖目录、构建产物和私人证据目录均应保持忽略。

GitHub Actions 使用相同的本地测试与构建流程发布固定演示，不向 GitHub 注入模型或麦当劳凭据。CI 通过不是模型效果指标，更不是获得奖项的保证。
