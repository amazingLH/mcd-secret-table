# 安装、运行与使用手册

## 1. 两种运行方式

| 方式 | 地址/命令 | 需要密钥 | 是否消耗模型额度 |
| --- | --- | --- | --- |
| 公开固定数据演示 | https://amazinglh.github.io/mcd-secret-table/ | 不需要 | 否 |
| 本机离线演示 | npm run dev 或 npm start | 不需要 | 否 |
| 本机真实协商 | 同上，手动选择真实模式 | MCP Token、百炼通用 API Key | 是，是否免费抵扣由百炼决定 |

公开页面没有部署持有密钥的后端，不能直接执行真实协商。这样不会把个人模型账户开放给任意访问者使用。

## 2. 安装与本地启动

要求 Node.js 22.9 或更新版本、npm，以及可访问相关官方服务的网络。

```powershell
git clone https://github.com/amazingLH/mcd-secret-table.git
cd mcd-secret-table
npm ci
npm run dev
```

打开终端实际显示的 Local URL。开发模式通常是 5173 端口，端口占用时以终端为准。首次进入默认离线演示，点击运行即可体验，不要为了看演示去申请或充值模型服务。

生产式本机运行：

```powershell
npm run build
npm start
```

默认地址为 http://127.0.0.1:4173/。`npm run preview` 仅提供静态文件，不提供真实 API。

## 3. 配置真实协商

先到 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp)申请 Token，并在自己的系统环境变量中保存 `MCD_MCP_TOKEN`。百炼 API Key 使用 `DASHSCOPE_API_KEY`。不要把密钥放进网页、Issue 或公开仓库。

本项目允许把**非敏感模型设置**保存在被 Git 忽略的 `.env.local` 中，例如：

```ini
AGENT_MODEL=deepseek-v4.1-flash
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
# 只有先核实当前模型的额度、有效期、地域与计费设置后，才添加下一行：
DASHSCOPE_BILLING_CONFIRMED_MODEL=deepseek-v4.1-flash
```

这段例子不包含密钥，也不表示任何账户一定有免费额度。启动命令读取 `.env.local`；已有系统或当前进程环境变量优先。`AGENT_MODEL` 优先于旧的 `QWEN_MODEL`。修改设置后重启服务。

免费额度通常按模型分别计算。不要因为某个 embedding 模型有额度，就把它用于生成餐单；这里需要支持工具调用的对话模型。建议先在百炼为目标模型保留“免费额度用完即停”，并等待保护生效。免费耗尽后是否继续付费，应在明确了解费用后由账户持有人决定，本项目不自动改变该设置。

计费确认变量只是调用开关，不会读取或锁定云端余额，也不能保护同一个 Key 在其他应用中的调用。

## 4. 页面使用顺序

1. 共同设置：城市、地点、公开总预算。
2. 本地条件舱：依次切换三位参与者并编辑条件。
3. 运行：离线演示不联网；真实协商读取官方菜单并调用模型。
4. 候选方案：查看编号、参考价格、最低/平均分和各人分数，展开查看分配。
5. 阅读说明：商品编码后自动补本轮菜单名称，`utility` 显示为满意度。模型文字不作为硬约束证明。
6. 最终餐单：通过方案名称和编号与候选列表对照，确认唯一采用的候选。
7. 真实核价完成后可下载 Markdown 摘要；下载包含最终分配和官方价格，不包含原始个人预算或偏好。

如果修改任何条件，已有结果会被清空，必须重新协商，不能拿旧结果冒充新条件的结果。

## 5. 测试与真实验收命令

```powershell
npm test
npm run build
```

上述命令不消耗真实模型额度。以下命令会访问外部服务，按需要运行，不会被本地单元测试自动触发：

```powershell
npm run model:check   # 一次最小真实模型工具调用，消耗少量额度
npm run mcp:inspect   # 列出官方工具
npm run mcp:verify    # 只读 MCP 验收，不调用大模型
npm run agent:verify  # 完整 API + MCP + 模型反馈验收，至少两轮真实模型调用
```

`agent:verify` 使用公开地点与合成条件，不下单，不支付。成功后更新 `evidence/live-agent.json`。不要为了验证显示文案反复运行它；编号转换、选中标记和评估规则可通过本地测试验证。

## 6. 常见情况

| 现象 | 含义/处理 |
| --- | --- |
| 真实协商按钮不可用 | 公网页面没有后端，或本机模型配置/计费确认未完成；查看页面提示 |
| AllocationQuota.FreeTierOnly | 云端免费额度保护阻止继续调用；先核对额度，不自动关闭保护 |
| 没有全员接受方案 | 条件可能冲突；调整条件或共同预算后重新开始，不保证每次有解 |
| 部分候选被淘汰 | 模型输出违反商品、主食、人数或预算约束；其余合法候选仍可评估 |
| 方案已接受但未采用 | 还需按排序进行官方核价；全员接受不等于最终确定 |
| 方案核价或复核未通过 | 当前无法作为最终结果；不能沿用核价前的接受状态 |
| 看到旧的“千问”标签 | 刷新页面；页面当前统一使用协调模型名称，历史截图保留原版本 |
| 刷新后条件消失 | 当前原型把条件放在页面内存，没有持久化存储 |

## 7. 开源更新与报名

项目源代码位于个人公开仓库 `amazingLH/mcd-secret-table`。将修改提交到该仓库 main 分支后，GitHub Actions 运行测试、构建并部署固定数据演示。不要另建一个同内容仓库分散提交记录。

报名 Issue 指向的是这个长期仓库地址，不是某次代码压缩包。仓库更新后，报名链接访问到的项目代码也随之更新；原 Issue 的描述可同步本阶段功能和验证结果，无需重复报名。官方账号的参赛确认评论不属于本项目，不能编辑或冒充官方更新。
